Get Your Hands Dirty

Hands-On Lab Center

Guided, beginner-to-advanced labs with prerequisites, plain-language setup, task steps, success checks, safe failure drills, and cleanup.

Start here · how to use a lab
  1. Follow the stages in order at first. The prerequisites tell you what to learn before a lab; if a term is new, open its linked stage.
  2. Use a disposable local VM, container, or sandbox that you own. Read the safety note before running commands or creating cloud resources.
  3. Follow each numbered instruction in order and save the command output, screenshot, or configuration that proves what happened.
  4. Use the acceptance criteria as the finish line. Then try the validation exercise, restore the healthy state, and complete cleanup.
  5. Write down what you learned in Personal notes. Repeat the lab from a clean state before moving to a related portfolio project.

Terms: prerequisites are the knowledge and tools needed first; acceptance criteria describe what “done” looks like; validation checks the result and a safe failure; cleanup removes temporary resources.

Full production delivery loop · 6 checkpoints
  1. Pin a release or commit, fork it for your work, read the license, map its services, dependencies, data, and trust boundaries.
  2. Run the smallest supported local deployment first; record resource use, health checks, ports, persistent volumes, and teardown commands.
  3. Build a CI path that tests the app, scans dependencies and images, emits an SBOM, and publishes an immutable image digest.
  4. Deploy to an isolated environment with managed secrets, least-privilege identity, network boundaries, and explicit cost limits.
  5. Define user-facing SLIs and an SLO, add dashboards and alerts, generate load, and diagnose one controlled failure from telemetry.
  6. Practice a staged release, rollback, backup, isolated restore, and full teardown; save sanitized evidence and a runbook.

Training scope: Gitea and Nextcloud are real open-source applications with their own deployment guidance; the AWS Retail Store and Astronomy Shop are reference/demo workloads. In particular, the AWS project says it is educational use only and not for production. Treat every deployment as a lab until you have reviewed and adapted it for your own service.
